# راهنمای شروع و فهرست API

[فارسی](GETTING_STARTED_FA.md) | [English](GETTING_STARTED.md)

## ساختار مخزن

این مخزن مجموعه‌ای از پوشه‌های مستقل است، نه یک target واحد برای build. فقط اجزای موردنیاز را ادغام کنید. در این بررسی، سیستم build/test یکپارچه و تأییدشده‌ای برای کل مخزن احراز نشد.

## روش پیشنهادی ادغام

1. مدل دقیق MCU و برد را مشخص کنید.
2. پروژه‌ای در STM32CubeIDE/STM32CubeMX بسازید و کلاک، GPIO و وسایل جانبی را تنظیم کنید.
3. README همان جزء و فایل‌های منبع/هدر آن را بررسی کنید.
4. فایل‌های لازم را اضافه و مسیرهای include را تنظیم کنید.
5. نسخهٔ HAL/CMSIS و سطح زبان C++ را تطبیق دهید.
6. با هشدارهای کامپایلر build بگیرید.
7. با debugger و روش بازیابی مطمئن روی سخت‌افزار آزمایش کنید. پاک‌کردن فلش یا تغییر read protection را روی تنها نسخهٔ firmware مهم آزمایش نکنید.

## فهرست APIهای بررسی‌شده

### QBuffer — QBuffer/QBuffer.hpp

- QBuffer(uint32_t bufferSize): تخصیص بافر با ظرفیت مشخص.
- Flush(): خالی‌کردن محتوای منطقی.
- Push(uint8_t data): افزودن بایت؛ هنگام پر بودن، رفتار حلقوی ممکن است دادهٔ خوانده‌نشده را بازنویسی کند.
- Pop(): برگرداندن بایت بعدی یا 1- در حالت خالی.
- GetLength() const: تعداد بایت‌های موجود.
- PeekAt(uint32_t index) const: خواندن بایت یا 1- برای اندیس نامعتبر.
- Remove(uint32_t num): حذف بایت‌ها از ابتدای بافر.

این کلاس مالک pointer خام است و عملیات copy/move اختصاصی ندارد؛ کپی‌کردن شیء می‌تواند باعث آزادسازی دوبارهٔ حافظه یا خرابی حافظه شود.

### QCRC — QBuffer/QCRC.hpp

تابع QCRC::CRC_8_CCITT از مقدار اولیهٔ 0xFF و چندجمله‌ای 0x07 استفاده می‌کند. همهٔ پروتکل‌هایی که نام CRC-8/CCITT دارند پارامترهای یکسانی ندارند؛ آن را با مشخصات دستگاه مقصد تطبیق دهید.

### QPacket / QCommand — QBuffer/

QPacket.hpp بسته‌ای با نشانگر شروع 0xAA، پایان 0xBB، شمارنده، فیلد طول و CRC می‌سازد. QCommand.hpp بسته‌ها را از QBuffer اعتبارسنجی/تجزیه می‌کند. بسته‌های ناقص، خراب، حداکثری و چند بستهٔ پشت‌سرهم را آزمایش کنید.

### FlashEEPROM — FlashEEPROM/FlashEEPROM.hpp

این کلاس pointer و اندازه می‌گیرد، آدرس فلش را از macroهای خانوادهٔ MCU محاسبه می‌کند و متدهای WriteStruct() و ReadStruct() دارد. WriteStruct() پیش از نوشتن ناحیهٔ محاسبه‌شده را پاک می‌کند.

**هشدار حیاتی:** تا زمان بررسی آدرس، فیلدهای API پاک‌کردن، اندازهٔ صفحه/بانک، دانه‌بندی نوشتن، نواحی رزروشده و linker layout برای MCU دقیق از آن استفاده نکنید. آدرس اشتباه می‌تواند firmware یا داده‌های برنامه را پاک کند. متدهای فعلی خطاهای HAL را به فراخواننده گزارش نمی‌کنند.

### PrintfUart — PrintfUart/PrintfUart.h

سازنده handle مربوط به UART و گزینهٔ echo را می‌گیرد. printf(...) خروجی قالب‌بندی‌شده می‌فرستد و scanf(...) تا CR/LF دریافت کرده و متن را تجزیه می‌کند. پیاده‌سازی در هدر است و به main.h پروژه وابسته است.

دریافت ورودی مسدودکننده است و از HAL_MAX_DELAY استفاده می‌کند؛ پیش از استفادهٔ تولیدی، مسیرهای timeout و خطا را بررسی کنید.

### Servo — ServoMotor SG90/Servo.h

هدر، سازندهٔ Servo و متدهای begin() و setAngle(uint8_t) را ارائه می‌کند. هدر HAL فعلی مخصوص STM32F1 است. پریود و prescaler باید با کلاک واقعی تایمر و MCU هدف تطبیق داده شوند.

### FFT — FFT(STM32H743VITx)/README.md

مثال، FFT حقیقی CMSIS-DSP روی STM32H743 را شرح می‌دهد. نسخهٔ CMSIS-DSP، اندازهٔ FFT، لینک‌شدن کتابخانه، تنظیمات ممیز شناور و نرخ نمونه‌برداری را بررسی کنید.

### مثال‌های Bootloader و read protection

پوشه‌های BOOTLOADER/ و Lock_program_in_code/ مثال‌های وابسته به MCU دارند. تا زمان بررسی نقشهٔ حافظه، option bytes و روش بازیابی بر اساس مستندات دقیق دستگاه، آن‌ها را آزمایشی در نظر بگیرید.

## وضعیت build و آزمایش

دستور build عمومی برای کل مخزن در این مستند تأیید نشده است. هنگام تهیهٔ این مستند، کامپایل، تحلیل ایستا یا آزمایش سخت‌افزاری انجام نشده است. برای هر ادغام معتبر، مدل MCU، نسخهٔ کامپایلر، نسخه‌های HAL/CMSIS، خروجی build و نتایج آزمایش را ثبت کنید.

## پیش از استفادهٔ تولیدی

- محدودهٔ بافر و ورودی‌های خراب را بررسی کنید.
- مقدار بازگشتی HAL و مسیرهای timeout را بررسی کنید.
- مرزهای فلش و اندازهٔ پاک‌کردن/نوشتن را تأیید کنید.
- هم‌زمانی، وقفه‌ها و استفاده از taskها را بررسی کنید.
- مجوز هر جزء و تمام وابستگی‌های خارجی را تأیید کنید.
