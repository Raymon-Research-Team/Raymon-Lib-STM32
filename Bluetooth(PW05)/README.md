# PW05 Bluetooth UART Module

`PW05_Bluetooth.hpp` provides a C++ wrapper for a PW05-style Bluetooth module using STM32 HAL UART and GPIO APIs. The exact command set, pin polarity, and supported features depend on the module firmware revision; verify the module's own datasheet before use.

## Requirements

- STM32Cube project with `main.h` exposing the correct HAL and GPIO definitions.
- A configured `UART_HandleTypeDef* ` connected to the module's UART pins.
- GPIO outputs connected to the module's AT-mode and sleep/enable pins, plus a GPIO input for status.
- Correct UART baud rate, voltage levels, common ground, and TX/RX crossover.
- C++ compilation enabled for the translation unit including this header.

## Construction

```cpp
#include "PW05_Bluetooth.hpp"

PW05_Bluetooth bluetooth(
    &huart1,
    BT_AT_GPIO_Port, BT_AT_Pin,
    BT_SLEEP_GPIO_Port, BT_SLEEP_Pin,
    BT_STATUS_GPIO_Port, BT_STATUS_Pin
);
```

Replace `huart1` and the GPIO identifiers with names generated by your own STM32Cube project. Ensure the constructor's GPIO arguments match the actual module wiring.

## Main API

The header includes methods for enabling/disabling the module, switching AT mode, checking connection status, changing UART baud rate and device name, reading/setting the MAC address, sending/receiving data, disconnecting, saving settings, setting TX power and advertising interval, enabling advertising/SPP mode, role selection, scanning, connecting, and reading firmware/RSSI information.

Consult the declarations and implementation in `PW05_Bluetooth.hpp` for exact parameters and return types. Many configuration methods return `bool`; check the result rather than assuming a command succeeded.

## Integration sequence

1. Configure the UART and GPIOs in STM32CubeMX and generate `main.h`.
2. Verify module supply voltage and logic-level compatibility.
3. Start with the module's documented default UART settings.
4. Instantiate the class and test a single read-only AT query on a bench setup.
5. Configure one setting at a time, check the return value/response, and save only after confirming the module-specific command syntax.
6. Test data mode separately from AT mode.

## Important limitations and safety

- The implementation uses blocking HAL calls and may wait for long periods (some transmit calls use `HAL_MAX_DELAY`). Do not call it from a timing-critical ISR.
- The implementation uses fixed-size command/response buffers. Validate names and input strings; the current code should not be treated as hardened against arbitrary input.
- AT-mode, sleep-pin polarity, status-pin polarity, MAC formatting, and command responses may differ by firmware revision.
- `getMAC`, RSSI/version queries, scanning and connection methods should be checked carefully against the actual response format before relying on their output buffers.
- Protect shared UART access: do not let another task or interrupt use the same UART concurrently without synchronization.
- This component has not been confirmed on all STM32 families or physically tested as part of this repository.

This README describes the current code and does not certify every command as compatible with every PW05 module.
