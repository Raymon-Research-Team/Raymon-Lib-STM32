# cUart — C++ Streams over STM32 HAL UART

`cUart.hpp` defines a small C++ wrapper that exposes UART-backed `std::ostream` and `std::istream` objects. It can make stream-style input/output available in an STM32 project, but it depends on the C++ standard library and is not suitable for every embedded runtime.

## Requirements

- C++ compilation and a standard library implementation providing `std::streambuf`, `std::ostream`, and `std::istream`.
- STM32 HAL UART support and `main.h`.
- A valid, initialized `UART_HandleTypeDef* ` for the selected UART.

## Intended usage

```cpp
#include "cUart.hpp"

cUart console(&huart1);

// Example output:
console.cout << "Value: " << 42 << '\n';

// Example input (blocking until input is received):
int value = 0;
console.cin >> value;
```

Use the actual UART handle generated by your STM32Cube project. This wrapper creates its own streams; it does not replace global `std::cout` or `std::cin`.

## Blocking behavior

The current implementation calls `HAL_UART_Transmit` and `HAL_UART_Receive` with `HAL_MAX_DELAY`. Output/input can therefore block indefinitely if the peripheral or external sender does not make progress. Do not call these operations from an interrupt service routine or a real-time path that cannot block.

## Known limitation requiring correction before production use

The current `UartInput::underflow()` stores the received byte in a local variable and then passes its address to `setg()`. That pointer outlives the local variable when `underflow()` returns, so subsequent stream-buffer reads may access invalid memory. The implementation also does not check HAL return values, and `UartOutput::overflow()` passes the address of an `int` while requesting a one-byte transfer, which is not a robust portable character conversion.

**Do not rely on the current input/output adapter in production until these implementation issues are fixed and tested.** Prefer a persistent member buffer, explicit conversion to `uint8_t`, checked HAL status codes, and bounded timeouts.

## Validation

Build with the exact STM32 toolchain and standard-library configuration. Test single-character and multi-character input, line endings, timeout/error behavior, and concurrent access. No compile or hardware test is claimed for this README.
